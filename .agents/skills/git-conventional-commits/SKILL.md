# Git Conventional Commits Skill

## 概要
- バージョン管理において、コミットメッセージの品質と追跡性を高めるため、Conventional Commits 1.0.0 仕様に準拠したメッセージ作成を行います。

## 手順
1. **差分の評価**: `git diff --cached` などを用いて、どのような変更が含まれるかを分析します。
2. **タイプの分類**: 変更内容に基づき、適切なタイプを選択します。
   - `feat`: 新機能の追加
   - `fix`: バグ修正
   - `docs`: ドキュメントのみの変更
   - `style`: コードの意味に影響を与えない変更（ホワイトスペース、フォーマット、セミコロンなど）
   - `refactor`: バグ修正や新機能追加を行わないコードの書き換え
   - `perf`: パフォーマンス向上のためのコード変更
   - `test`: 不足しているテストの追加や既存テストの修正
   - `chore`: ビルドプロセスや補助ツールの変更、ライブラリの更新など
3. **メッセージの構成**: 
   - 1行目は `<type>(<scope>): <summary>` (1行で要約、50文字以内)
   - 2行目は空行
   - 3行目以降は必要に応じて、詳細な変更理由（Why）や破壊的変更（BREAKING CHANGE）の説明を記述します。
